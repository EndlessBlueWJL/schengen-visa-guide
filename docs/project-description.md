# Schengen Visa Skill — 项目说明

申根签证是中国护照持有者最常见的出境签证之一，DIY 申请需要按身份与申请国要求准备材料。市面上的攻略文章很多，但攻略是死的，它不能根据你的身份告诉你该走学生出资还是父母出资，也不能在你第二天打开电脑时记得你昨天办到哪了。这个 skill 做的事情，就是把一条死攻略变成一个能跨会话连续工作的交互式向导。

它解决的第一个痛点是流程碎片化。申根签 DIY 最难的不是填表，而是不知道该从哪一步开始，先订机票还是先做行程单，保险什么时候买，在读证明开了会不会过期。skill 把全流程固化为一条线性的步骤链，每一步完成之后自然推到下一步。

第二个痛点是跨会话记忆断裂。办签证通常要好几天，聊半小时办完了五项材料，关掉窗口，第二天 AI 连你在办签证都不知道。这个 skill 的核心改进就是引入了一个 progress 文件作为落盘机制，每次用户说某项材料好了，模型立刻写入文件勾掉对应的复选框。每次新会话启动，模型被强制要求先读取进度文件，确认上次办到哪了再从断点继续。用户不用复述，AI 先说。

第三个痛点是敏感信息与可生成内容之间没有边界。证件照、户口本、银行流水、在读证明属于敏感个人信息，AI 不应该接触，但行程单、解释信又完全可以帮忙生成。skill 预设了这条分界，通常只提醒敏感材料怎么办；用户明确选择并上传中文版《教育部学籍在线验证报告》时，可使用内置引擎生成英文工具译件及预览。原件、字段、照片、二维码和输出均保存在代码仓库外，程序不调用额外在线翻译服务，当前聊天平台仍会处理上传文件。

第四个痛点是申根二十九国各有一套流程，签证外包商不同，官网不同，领区划分不同。skill 内置了全部二十九国的官方直链，法意西三国还有详细步骤，用户选哪个国家就从 reference 文件里查哪个国家的链接和流程，不用自己搜。

架构上以 Markdown 定义流程，以仓库外的 progress.md 保存进度；主控文件 SKILL.md 负责六步主线和状态管理，五个 reference 文件按需提供材料清单、各国流程、解释信、行程单与学信网办理说明。可选的 Python 入口 scripts/translate_chsi.py 负责提取受支持的中文学籍报告并调用内置翻译引擎，无需数据库。

核心逻辑可拆为五个机制。一是会话启动门，每次新会话模型先读 progress 文件再回复用户，这是写死的强制指令。二是逐项推送加即时落盘，六步主线推进，材料阶段按证件、学生身份、保险、资金、行程单、机票、酒店、解释信的依赖链排序，用户说好了模型先写文件勾掉再回复，先存再回。三是申请国自适应路由，选国后从 country-notes 查直链和流程，这是查表不是推理。四是材料处理边界，证件和资金材料通常只提醒，行程单与解释信可生成，学籍报告在用户选择并上传后可翻译。五是最终确认，不是看清单全绿就完事，而是逐项再过一遍，连已勾掉的也要重新确认，因为勾选和材料真正就位之间可能有差距。

关于多 Agent 协作和长链推理，当前版本都没有。这是一个单人机交互式向导，智能不是来自模型自主规划，而是来自流程设计中的依赖关系预设、边界条件的硬约束和状态的落盘恢复。思路是把智慧写进文档结构里，让模型按文档执行，而不是让模型自己想怎么办。

目前面向中国大陆护照持有者，覆盖在校学生、在职、退休、自由职业、无业和未成年人六种身份，仅提供申根短期旅游签指导。学信网功能只支持已验证版式的单页文字型《教育部学籍在线验证报告》；工具译件是否接受，以申请国使领馆或签证中心要求为准。非申根国家不在本 skill 范围内。
